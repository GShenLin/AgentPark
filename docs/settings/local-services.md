# 本地服务 / LocalModel

[Settings 索引](README.md) · [模型配置](models.md)

入口：**Settings → 本地服务**。登记与管理的是运行 AgentPark 后端的那台设备上的服务，配置保存在 `config/localModel.json`。浏览器在另一台机器上打开，不会把本地路径变成浏览器设备上的路径。

## 1. 普通服务：先登记，再手动控制

1. 点击添加，保留“不使用预设”。
2. 填服务名称。
3. 需要由 AgentPark 启动时，填写启动程序的绝对路径和工作目录，再按一行一个参数填写启动参数。
4. 需要检测/打开页面时填写本机服务地址；已在外部运行的服务只登记名称和地址也可以。
5. 需要验证真正就绪时，填写健康检测路径和等待秒数。
6. 保存，选中该服务，手动检测或启动；核对状态、作业结果和错误详情。

### 字段逐项说明

| 字段 | 怎么填写 |
| --- | --- |
| 名称 | 用于列表区分的显示名称 |
| 工作目录 | 绝对路径；配置了启动程序时必填 |
| 启动程序 | 实际可执行文件的绝对路径；脚本应填解释器路径 |
| 启动参数 | 每行一个参数；路径即使含空格也不额外加 shell 引号 |
| 服务地址 | 本机 HTTP/HTTPS 根地址，如 `http://127.0.0.1:9000`；仅登记已有服务时必填 |
| 就绪检测路径 | 如 `/health`，GET 返回 HTTP 2xx 为通过，不跟随重定向 |
| 启动等待时间 | 有检测时使用，1–600 秒，默认 60 秒 |

例如启动 Python 服务：启动程序填写 `C:\Python312\python.exe`，工作目录填写 `C:\Services\Demo`，参数逐行填脚本绝对路径、`--port`、`9000`。这是字段示例，需要替换成实际安装位置。

服务地址不自动变成启动参数；服务实际监听地址由它自己的参数决定。未配置检测路径时只报告进程状态，`online` 可为未知，不能据此认定 HTTP 服务已经就绪。

## 2. 状态与操作边界

- **启动**：运行配置的前台程序。启动器必须保持运行，不能启动服务后立即退出或分离进程。
- **检测**：执行静态与连接检查，不执行模型推理；连接错误可展开查看。
- **打开**：打开登记的服务地址；这不是一次启动或授权操作。
- **停止**：仅停止当前 AgentPark 进程拥有的服务进程树。外部启动或后端重启前启动的实例，需回原入口停止。
- **编辑/移除**：先结束该实例正在进行的操作；移除登记不等于卸载服务软件或权重。

检测超时会保留进程供检查或手动停止，错误会明确显示。服务进程运行、端口监听、健康检查成功、模型推理成功是四个不同层次。

## 3. 使用管理预设

展开“使用管理预设（可选）”，选择 **Strata** 或 **ComfyUI**。它们额外提供专用启动、健康检查和模型操作。

| 字段 | Strata / ComfyUI 的用法 |
| --- | --- |
| 安装目录 | 分别为含 `serve/server.py` 或 `main.py` 的根目录 |
| Python 可执行文件 | 可显式指定；留空使用安装目录 `.venv`；便携 ComfyUI 需指定实际 `python_embeded/python.exe` |
| 附加启动参数 | 每行一个，例如 ComfyUI 的 `--lowvram` |
| 服务地址 | 带端口的本机根地址，不带 `/v1` |
| API 工作流文件 | 仅 ComfyUI；已导出的 API 格式 JSON 绝对路径 |

切换预设会重置服务地址、参数和专用设置，保留名称与目录；保存前重新核对。管理预设不会替你安装 Strata/ComfyUI，也不会自动下载权重。

## 4. Strata 模型管理

1. 登记安装目录，检测扫描到的 `strata*.json` 运行配置。
2. 核对配置引用的 engine、pack/native/PLE 路径。
3. 选择运行配置并启动 HTTP 服务；启动使用 lazy 模式，不加载权重。
4. 需要推理时手动加载，完成任务后卸载；查看 `/health` 与操作返回状态。
5. 切换不同运行配置前先停止当前实例，再启动新的配置。

添加模型登记已有运行配置，保留原权重位置，不做下载或格式转换。静态文件检查通过不代表格式一定兼容，仍需实际推理验证。

## 5. ComfyUI 模型与工作流

1. 检测安装目录、模型目录和 `extra_model_paths.yaml`；在线服务还会提供模型清单。
2. 使用名称/类型/路径搜索定位模型。
3. 添加已有本地模型时填写源文件绝对路径和类别；操作会复制到指定类别，不覆盖同名文件。
4. 指定 API 格式工作流 JSON，确认它引用的模型和节点确实存在。
5. 点击执行工作流会提交真实生成任务；在作业和 ComfyUI 中核对结果。
6. 队列为空后可释放模型。`/free` 是异步请求，界面只确认已提交，不宣称每个模型都已释放。

普通服务没有这些模型操作；选择 ComfyUI 预设也不会把任意单个权重变成通用可加载模型。

## 6. 与 Agent Provider 的关系

本面板负责服务生命周期；Provider 决定 Agent 通过什么协议调用它。想让 Agent 使用某个本地兼容模型，还需在 **模型提供商** 单独登记正确 Type、Base URL、模型和授权模式。启动服务不会自动修改既有 Provider。

所有操作均手动发起，不自动调度、不默认向 Agent 暴露管理工具。作业历史在内存中，重启不保留，服务配置保留。更多协议边界见 [本地服务专题](../local-model.md)。
