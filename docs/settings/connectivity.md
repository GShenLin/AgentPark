# 设备互联、远程执行与节点同步

[Settings 索引](README.md) · [权限](access-gateway.md)

先区分四种目标：

| 目标 | 使用什么 | 任务实际在哪里 |
| --- | --- | --- |
| 从另一端操作某台电脑的完整工作台 | 云端设备中心 → 打开 Board，或可达的后端地址 | 目标设备后端 |
| 查看/操作另一后端授予的公开节点 | 设备互联中的远程工作区 | 对方后端 |
| 当前节点使用另一台机器的文件与命令环境 | LinkToRemote / 远程执行设备 | 支持该操作的远端执行器 |
| 复制对话或图结构到另一位置 | 节点同步 | 目标获得副本，不自动开始执行 |

<a id="peer-network"></a>
## 1. 设备互联

入口：**Settings → 设备互联**。使用云端鉴权与信令服务建立 WebRTC，优先直连，必要时 TURN 中继。业务数据端到端加密；设备注册与业务授权分别管理。

### 本机连接设置

| 字段 | 如何填写 |
| --- | --- |
| 本机名称 | 设备中心显示名称，默认取系统计算机名；修改不改变设备身份 |
| 鉴权服务器 IP | 部署的鉴权中心 IP 字面地址，不填域名、URL、端口或路径 |
| 启用设备互联 | 开关；保存后建立/更新连接 |
| 设备身份 | 用于云端确认时核对的设备编号，不是密码 |

1. 从本机访问设置，核对名称与所用鉴权中心，保存。
2. 点击“打开云端设备中心”，用该中心的管理员密码登录。
3. 对新设备核对完整身份编号，批准接入。
4. 等待本机自动重连成为在线设备，再在设备中心选择 **打开 Board**。
5. 检查页面显示的直连或中继状态，再使用目标设备的画板。

现有代码的新设备默认启用互联，默认中心 IP 为 `203.0.113.10`；这是公开仓库的文档示例地址，不能用于连接；使用前必须配置自己的中心地址和账号。自建环境填自己的中心，或按需求关闭。公网使用可信 HTTPS/WSS，私有 IP 证书部署需安装对应信任；证书错误不会自动改用明文。

首次接入许可绑定设备公钥，不只绑定显示名称。复制部署时不要复制 `.auth/peer-network/identity.json`，应让新实例生成自己的身份。

### 从云端打开 Board

云端托管页面、鉴权及信令，设备后端仍保管 Graph、模型配置与运行状态。拥有云端管理员登录和有效设备票据的 Board 获得设备管理权限；这与普通远程用户的 Developer 勾选是不同入口。

断线时页面显示重连并暂禁操作；后端继续执行的任务不因浏览器断开而自动回滚。恢复后按服务反馈刷新状态，已经发送的写操作不会仅因断线而自动重复。设备侧后端必须保持运行，主机休眠或进程退出不能靠打开网页补足。

### 两台后端之间的共享授权

展开 **设备之间的共享与 Agent 协作（可选）**：

1. 填对方设备编号和备注名称。
2. 填共享 Graph ID，多个用逗号分隔；留空不共享画板。
3. 明确授予 view、control、collaborate，保存设备授权。
4. 在设备列表连接，查看状态与错误。
5. 对方也需按自己的共享目标配置对应授权。

| 权限 | 允许什么 |
| --- | --- |
| 查看节点和对话 / view | 列出授予范围内的公开画板、公开节点，读取对话 |
| 发送消息与停止 / control | 向目标发送消息或停止执行 |
| Agent 消息协作 / collaborate | 节点通过互联工具投递协作消息 |

仅加入同一个鉴权中心不等于双方已经授予这些业务权限。Graph 和节点还需公开。撤销授权关闭后续通道，不撤回已经入队的任务；需要时另外停止节点。

### 远程工作区

连接成功后点击打开远程工作区，依次选择 Graph、节点，加载/刷新对话。界面会标注最近对话或完整历史，发送消息后查看接收凭证，再刷新确认执行结果。

`queued` 仅表示已入队，不是已完成。停止按钮发起停止请求，最终状态仍需刷新确认。没有共享内容时先检查权限、Graph ID 和公开属性。

### Agent 消息协作

需要协作的节点选择 `peer_network_tools`，并确保双方设备授权。任务中明确目标设备、Graph、节点和交接内容；目标 Agent 自己处理和回复。发送超时可能产生不确定结果，应先查目标对话/凭证，不盲目重放相同业务操作。

## 2. 远程执行设备

设备互联页面中的 **远程执行设备** 会列出已登记的在线 AgentPark 和 Remote，显示在线状态、连接类型、主机类型、默认工作目录及能力列表。

1. 在远端部署并启动 Worker 或 AgentPark，完成同一鉴权中心审核或所需登记。
2. 刷新执行设备列表，核对目标名称、ID、在线状态与能力。
3. 回到需要工作的节点，右键 **LinkToRemote** 选择目标。
4. 设置远端存在的工作目录，先验证读取文件/平台信息，再运行命令。

目录与 shell 都属于远端。Windows 路径不能原样当作 Linux 路径，PowerShell 命令也不能当成 POSIX 命令。并非每个本地工具都支持远端，例如当前本地异步命令会话不能自动变成远程会话。

这不会将控制端上的所有 CLI 登录与 Skill 自动搬到远端。部署步骤见 [Linux Remote Worker](../../deploy/remote-worker/README-linux.md)。

<a id="node-sync"></a>
## 3. 节点同步

入口：**Settings → 节点同步**。来源 → 目标为单向提交；反向同步须交换选择并重新预览。

### 连接与选择两端

1. 需要云端设备时点“连接远程设备”，输入同一设备中心密码。
2. 服务器地址沿用设备互联设置；登录后刷新列表。
3. 来源和目标分别选远端、Graph、节点。
4. 可在目标端点击新建目标 Graph，填唯一 ID（英文、数字、下划线、横线）和可选显示名称。
5. 两边都选具体节点，或两边都不选节点；不能混用节点和整图模式。

登录密码不保存，会话只在当前 AgentPark 服务内存中，重启需重新登录。若目标实例要求用户身份，会弹出用户名登记。上次设备未连接时需重新加载，而不是对过期设备条目提交。

### 预览、提交和继续

1. 点击 **预览同步**，等待后台生成清单。
2. 检查新增、更新、未变化的消息数、附件数量/大小、结构变更、分组变化与警告。
3. 存在冲突时先解决再重新预览。
4. 确认选择和预览一致后点击 **开始同步**。
5. 等待已提交节点计数完成，打开目标核对关键对话和附件。
6. failed / interrupted 且选择仍一致时，可点 **继续上次任务**；更换来源或目标必须重新预览。

关闭设置页不会停止已开始后台任务。目标正在执行或排队时拒绝提交，待其空闲后重试。远端两端都需支持当前同步协议。

### 同步内容与覆盖规则

| 内容 | 节点模式 | 整图模式 |
| --- | --- | --- |
| 用户消息、最终回答、附件、Archive | 增量合并 | 各节点分别合并 |
| Process / 工具过程明细 | 不传输 | 不传输 |
| 节点配置、位置、连线、分组 | 不作为单节点对话同步内容 | 按节点 ID 对应，已有同名结构配置以来源为准 |
| 目标已有额外对话/节点 | 保留目标已有对话 | 保留目标额外节点 |
| 删除操作 | 不同步删除 | 不同步删除 |
| 模型账号、插件安装 | 不复制 | 不复制 |
| 任务队列、组内动态 | 不复制 | 不复制 |
| 工作路径 | 不迁移执行环境 | 配置中的路径原样复制，目标需自己核对可用性 |

同步不触发 Agent 工作，也不是完整设备备份。完成后还需核对目标 Provider/预设引用、账号和工作目录，再决定是否启动目标节点。协议、日志与冲突细节见 [节点同步专题](../node-sync.md)。

部署与安全边界见 [P2P 专题](../peer-network.md)。
