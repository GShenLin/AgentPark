# Knowledge：添加资料、建立索引并交给 Agent 使用

[Settings 索引](README.md) · [Skills](skills.md)

入口：**Settings → Knowledge**。它直接读取后端设备上的文件夹，保留源文件，建立磁盘索引并通过你配置的 Embedding 服务向量化。首次扫描和语义查询会调用模型服务，耗时与费用取决于数据量和服务。

## 1. 添加文件夹知识库

1. 点击 **添加文件夹知识库**。
2. 填名称和资料文件夹；路径属于后端设备，可用“选择文件夹”选择。
3. 填 Embedding Base URL 或完整接口地址，核对实际请求地址；支持 OpenAI 文本 `/embeddings` 和方舟 `/embeddings/multimodal` 文本输入协议。
4. 填准确的 Embedding 模型 ID，选择 API Key 别名；通过 Add 可添加密钥。无认证本地服务可选 Unset。
5. 决定是否“允许通过 MCP 访问”；开启后，连接 AgentPark 自身 MCP 的客户端可发现和读取该库。
6. 需要时配置分块、表头和资源限制，保存。
7. 在卡片上先 **测试模型**，再 **开始 / 增量扫描**。

保存仅登记知识库，不自动开始处理资料。向量维度由测试/索引响应检测；不同模型或维度的数据使用独立索引。

### 影响索引的配置

| 字段 | 作用 | 创建后 |
| --- | --- | --- |
| 资料文件夹 | 索引根目录，递归读取支持的文件 | 可修改，切换新索引 |
| Embedding URL | 接口地址，显示归一化后的实际请求地址 | 可修改 |
| Embedding 模型 | 文本向量空间的模型标识 | 可修改；向量空间变化时切换新索引 |
| 分块字符数 | 每个文本片段的目标上限，256–8000 | 可修改，切换新索引 |
| 重叠字符数 | 相邻片段重叠，0–1000，且小于分块字符数 | 可修改，切换新索引 |
| Excel 表头行 | 0 不指定；1 表示第 1 行；为片段附带统一列名 | 可修改，切换新索引 |

保存影响索引的修改时，界面会提示切换新索引，原索引保留，随后手动开始扫描。仅修改 MCP 开关、名称、密钥或同一向量空间的接口配置不会重建索引。资料内表头不统一时保持 0，读取/统计时明确坐标。

### 可以调整的处理参数

| 字段 | 范围/含义 | 调节场景 |
| --- | --- | --- |
| 名称 | 显示用途 | 区分项目与资料类型 |
| API Key | 选择已有别名 | 更新账号或修复认证 |
| 允许通过 MCP 访问 | 开关 | 控制 AgentPark `/mcp` 的 `get_knowledge` 访问；不影响节点的 Knowledge 选择 |
| 每次 Embedding 片段数 | 1–128 | 服务批量上限、吞吐与限流 |
| 请求超时 | 5–300 秒 | 单批处理较慢 |
| 429 重试等待 | 1–300 秒，默认 5；每批最多重试 3 次 | 服务限流 |
| 单文件上限 | 1–4096 MB | 控制过大文件的资源使用 |
| 单页字符上限 | 10000–2000000 | 防止异常页面占用资源 |

扩大资源上限不保证所有文件都能处理；损坏、加密、无文本 PDF、超限和缺少解析器均会显示错误。

## 2. 扫描、暂停、继续与更新

| 按钮/状态 | 如何理解 |
| --- | --- |
| 测试模型 | 真实验证接口和维度；不等于整库已完成索引 |
| 开始 / 增量扫描 | 扫描新文件与变化文件，解析并向量化 |
| 暂停 | 当前处理步骤结束后暂停，不是立刻杀死所有工作 |
| 继续任务 | 接续未完成阶段 |
| 重试失败文件 | 修复认证/解析环境/坏文件后重新处理错误条目 |
| 刷新 | 读取最新库状态，不自动开始扫描 |

卡片分别显示发现文件、可检索、待解析、待向量化、失败与向量片段数，以及当前路径、阶段和错误。只有成功发布的数据可检索。更新中的文件可能暂时保留上一次成功索引，界面会注明；不要把旧结果当作更新已完成。

资料修改后手动增量扫描。当前不做 OCR，也不遍历被排除的链接/junction。大资料库应预留索引空间，先用小文件夹验证模型与资源参数，再处理整个资料目录。

## 3. 在设置页验证检索

1. 点击目标库的 **文档与检索测试**。
2. 输入一个资料中确实存在的关键词或问题。
3. 先用关键词模式查原文标识，再用语义或混合模式验证自然语言检索。
4. 检查片段内容和出处，注意 partial、文件更新与警告提示。
5. 用文档状态筛选失败/已完成/待处理/待向量化条目，分页定位问题文件。

| 检索模式 | 用途 |
| --- | --- |
| Keyword | 文件中准确存在的名称、编号、短语 |
| Semantic | 语义接近、表述不同的问题，依赖 Embedding 服务 |
| Hybrid | 综合语义与关键词结果 |

关键词无结果时先检查索引状态；语义失败而关键词可用时检查 Embedding 查询的连接与授权。检索展示的是相关片段，不能把几个片段的数字相加当作全库统计。

## 4. 让 Agent 使用知识库

1. 在目标普通 Agent 的 **Knowledge** 选项中勾选一个或多个知识库。
2. 保存节点配置；内部 knowledge 技能自动启用，不需要在 Skills 中手动选择。
3. 发起新任务，例如：“在知识库‘项目笔记’中检索发布约束，读取原文核对后列出结论和出处。”
4. 在过程里确认 Skill 激活和对应查询，再检查最终回答的来源。

能力包括列库/文档、检索、分页读取原文，以及对 Excel 指定工作表与行范围做显式统计。节点只能访问自身 `knowledge_ids` 中的库；不选库就不启用内部技能。原文作为资料处理，不自动成为模型的系统指令。

### 通过 AgentPark 自身 MCP 访问

连接现有 `http://后端地址:8788/mcp/`（`agentpark-companion`）即可使用 `get_knowledge`，无需创建节点或启用 Skill。库配置中的“允许通过 MCP 访问”决定哪些库公开给连接该服务的客户端，与节点勾选互相独立。旧 `allow_agents` 配置迁移为 `allow_mcp`，保留开关值和索引。

`get_knowledge` 不带参数返回公开库的 ID、名称、只读权限与操作说明。后续仍调用同一工具，在 `request` 中传入操作：

```json
{"request":{"action":"list","library_id":"库ID","limit":50}}
```

```json
{"request":{"action":"search","library_id":"库ID","query":"激活函数","mode":"hybrid","limit":10}}
```

```json
{"request":{"action":"read","library_id":"库ID","chunk_id":123}}
```

```json
{"request":{"action":"table","library_id":"库ID","document_id":456,"sheet":"销售","start_row":2,"metrics":[{"name":"总额","op":"sum","column":"C"}]}}
```

`list` 可用 `after` 分页；`read` 可改用 `document_id` 并通过 `sheet`、`offset`、`limit` 读取原文。完整参数在 MCP `tools/list` 的 schema 中提供。每次请求都检查当前开关，关闭后新的调用立即失去访问权限；发现操作不签发永久授权。关键词检索不调用向量模型，语义和混合检索仍使用该库的 Embedding 配置。检索或模型错误会直接返回，不会静默改用其他模式。

## 5. 各格式如何使用

| 格式 | 可获得的内容与出处 | 限制 |
| --- | --- | --- |
| PDF | 文本与页码 | 不做 OCR，扫描图片 PDF 可能无文本 |
| Markdown / TXT | 文本与行位置 | 以扫描版本为依据 |
| DOCX | 正文、普通表格、独立页眉页脚；段落/表格位置 | 不伪造渲染页码；图片、复杂文本框和修订不保证完整 |
| DOC | 转换后解析 | 后端需 LibreOffice，可用 `AGENTPARK_LIBREOFFICE` 指定程序绝对路径 |
| XLSX / XLS | 工作表、行列、单元格保存值 | 图表/图片/宏不参与；Office 临时锁文件跳过 |

Excel 统计应明确“工作表、起止行、列、过滤、分组、聚合方式”。例如请求读取表头确认列后，再统计第 2–500 行某列的总和，并报告计算范围。

公式不会重算。XLSX 缺失参与统计所需的公式缓存会报错，应在表格软件中重算并保存后重新扫描；XLS 只提供保存值，无法判定公式缓存状态。隐藏行列会纳入显式范围，合并单元格不自动填充。

## 6. 常见问题

| 现象 | 处理 |
| --- | --- |
| 保存后可检索数量为 0 | 测试模型，再点击开始扫描，查看具体阶段 |
| 401 / 模型不存在 | 检查密钥别名、实际 URL 和 Embedding 模型 ID |
| 429 | 降低 batch size，按实际额度调整等待，保留错误证据 |
| DOC 解析失败 | 检查 LibreOffice 是否安装、路径和转换错误 |
| 新内容搜不到 | 增量扫描是否完成，是否还在显示旧发布版本 |
| 管理页可查，Agent 不可查 | 检查节点 Knowledge 选项及新任务是否已装载 |
| MCP 看不到知识库 | 检查该库的“允许通过 MCP 访问”（allow_mcp）是否已保存 |
| 统计与 Excel 显示不一致 | 起止行、隐藏行、公式保存值、表头与过滤条件 |

更多解析、分页和统计上限见 [Knowledge Office](../knowledge-office.md)。源码入口：`KnowledgeLibraryForm.vue`、`KnowledgeSettingsPanel.vue`、`src/knowledge/`。
