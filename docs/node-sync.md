# 节点与 Graph 同步（协议 v1）

入口：设置 → 节点同步。来源和目标分别选择远端、Graph、节点；两端必须支持本协议，并授予当前连接开发者权限。远端同时支持当前服务的手动远端配置和云端设备中心中的远程设备，选择器不会切换看板的全局远端。

## 云端远程设备

- 在同步页点击“连接远程设备”，使用设备中心的管理员密码登录；服务器地址沿用“设备互联”的配置。浏览器的云端登录 Cookie 不会复制给本地服务，因此首次使用需要在这里登录一次。
- 登录后，来源和目标下拉框显示在线云端设备；可以本机与云端同步、手动远端与云端同步，或两台云端设备之间同步。未启用云端访问的设备显示为不可选。离线设备不在在线列表中；断开或重新上线后点击“刷新列表”。
- 目录查询和同步协议复用签名 Board ticket、WebRTC 数据通道及现有 STUN/TURN。传输优先直连，必要时中继，不需要远端开放 HTTP 端口。对端需要支持节点同步协议，设备中心无需升级后端协议。
- 密码不写入配置、任务或日志；登录 Cookie、临时身份和 TURN 凭据仅保存在服务内存中。服务重启后重新登录，再继续上次任务。关闭设置页不会停止已开始的传输。
- 本机管理员和经过设备中心认证的云端管理员分别使用自己的登录会话；普通共享 Peer 或 LAN 开发者不能继承这些会话。云端 Board 重连产生的新临时连接身份仍代表同一设备中心管理员，可以继续任务。
- 云端错误、离线、旧版本、登录过期明确显示。传输失败不会自动重发写入；继续任务时复用已完成的分块和节点提交。

## 使用方式

1. 两边都选择节点：只同步节点对话记忆，不修改节点配置。
2. 两边都不选择节点：同步 Graph 结构及各节点对话。可在右侧创建空目标 Graph。
3. 点击预览：后端生成持久化快照、分块传输并比较目标，显示新增、更新、跳过数量、附件大小和结构变更。
4. 点击开始同步：应用结构后逐节点提交记忆。关掉设置页不影响后台任务；重新进入可看到上次任务。
5. 网络错误或服务重启后可继续上次任务。目标正在执行/有排队任务时拒绝该次提交；目标空闲后重试。已经成功的节点不重复提交。需要读取更新的来源内容时重新预览。

## 数据边界

- 当前与 `archive/YYYY-MM-DD/messages.jsonl` 中的 `user/human` 和 `assistant/agent` 记录；保留 ID、时间、trace 和消息 parts。
- 不复制 `assistant_progress`、`tool`、`metadata`、系统状态、运行日志、上下文 checkpoint 或长期记忆数据库。
- 系统错误和没有用户轮次的孤立回答在预览说明中列出，不伪造成最终回答。运行中的来源仅包含已落盘内容；后续落盘回答可再次增量同步。
- 显式资源附件按 SHA-256 传输，目标保存在所属节点 `sync_attachments`，重写 URI。HTTP/HTTPS/data 资源引用保留原样；正文中提到的任意项目路径不作为附件扫描。缺失的本地附件直接报错。
- 归档移动不是新消息。按整个逻辑节点和来源身份查重，保留完整轮次，避免两个节点同时间的问答交错。
- 更新来源消息时，只有目标仍等于上次已应用版本才更新。目标已修改或已删除的记录报冲突；不传播来源删除。
- 用户明确清空整个目标节点记忆时会同时重置该节点的同步索引，之后可以主动重新导入；单条删除仍按冲突保护。

## 整图语义

- 节点按 ID 对应，包含配置、工作路径、工具选择和位置；目标额外节点保留。节点类型不同则报冲突，目标未安装节点类型也报错。
- 来源节点的出线、节点备注按来源更新；目标独有节点的出线和备注保留。
- 分组按 ID 同步名称、目标描述、范围、成员和可见性；目标额外分组保留。一个节点不能因此属于多个分组。
- 目标已经私有的 Graph、节点、分组保持私有，不因来源公开而放宽访问范围。
- 不复制组内动态、任务、投递队列、当前执行状态、计时器运行状态或全局 Provider 登录/密钥配置。目标已有分组任务保留，不生成分组事件/投递，不触发 Agent 执行。
- Provider ID 和工作路径原样复制，需在目标机器具备相应 Provider、工具、MCP、插件和文件。预览会列出 Provider 引用。同步不是插件/工程文件安装器。
- 含私有节点/分组的整图导入导出需要目标/来源现有权限规则允许完整访问，不能利用同步绕过私有范围。

## 提交和恢复

协调任务、快照、导入计划、分块缓存保存在各端 `.cache/node-sync`；节点原始身份和已应用版本索引分别为 `.sync-origin.json`、`.sync-index.json`。缓存由内容哈希复用，v1 不自动清除历史任务缓存。

传输块为 256 KiB，低于 peer 单包限制。更新以节点为事务边界，并持久化每个完成步骤；整图不是跨机器全局事务，错误发生时已成功步骤保留，界面明确显示失败和完成节点数。结构文件按预览前/预期后状态检查，重试接受已应用的相同内容，拒绝覆盖预览后的编辑。

节点内用已有内存队列与跨进程记忆锁串行提交；写入 redo journal 后恢复所有受影响 JSONL、Markdown、来源索引，并失效派生上下文。普通记忆读取/写入也会先恢复未完成 journal。执行状态锁与运行器领取任务使用相同锁，确保提交不会与目标工作启动交错。

清单当前包含来源范围的完整用户/最终回答投影；目标仅写差量，已存在附件不重传。v1 没有只请求“新增清单页”的网络优化，也不把源端删除视为远端删除指令。

## 验证

`tests/test_node_sync.py`：Archive、过滤、附件、重复同步、更新/冲突、往返、迟到回答、繁忙保护、journal 恢复、Graph/Group 结构。

`tests/test_node_sync_api.py`：真实应用路由、真实节点配置、异步任务、开发者权限。

`tests/test_node_sync_transport.py`：两个独立 HTTP 服务、附件分块、目标写入后响应丢失、恢复继续、任务结果落盘。

`tests/test_node_sync_cloud.py`：真实设备中心、两个独立 WebRTC 设备、管理员登录与签名 ticket、目录、Archive 与附件、整图结构、重复同步、写入响应丢失后的继续、连接重建、退出登录及权限隔离。
